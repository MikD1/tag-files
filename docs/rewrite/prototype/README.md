# Согласованный целевой UX-макет Tag Files

14 ноября 2026 владелец продукта утвердил текущий макет и его реализованное пользовательское поведение как целевой интерфейс новой версии — D-16 в [реестре решений](../06-product-questions.md). Это baseline `tag-files-ui-v1` (итерация v27), а не набор вариантов для дальнейшего выбора. Он включает Library, Collections, Tags, Categories, Uploads, единый viewer и редактор. [Паспорт baseline](accepted-baseline.json) фиксирует точную сборку и hashes исходников. Макет создан 11 ноября; D-12…D-15 и последующие согласованные уточнения входят в принятую версию. Он не подключается к настоящей библиотеке, базе или хранилищу и не реализует production rewrite.

По обратной связи владельца визуальный контракт уточнён в D-12: контент и теги вместо просмотра файлов. У готовых материалов нет названий; галерея и viewer не показывают filename, вымышленные заголовки, размеры, байты, MIME, даты, описания и постоянные объясняющие тексты. Навигация, favorite, редактирование тегов/одной коллекции и media-controls доступны компактно. Имена иконок доступны через tooltip и assistive technology; ошибки появляются по ситуации. Отдельной кнопки справки поиска нет. Длительность видео остаётся частью его просмотра.

По D-13 интерфейс и демонстрационные теги, коллекции и сохранённые поиски английские. Это относится также к errors, empty states, help, tooltips и accessible names. Типы — две независимые icon-toggle Image/Video, Sort открывает меню семи English-пунктов с иконками, добавление представлено icon-only control только в Uploads. Кнопки сохраняют focus/keyboard, доступные имена и выбранное состояние. Данная документация остаётся на русском; реальные пользовательские Unicode-данные не переводятся и языковой switch не добавляется.

По D-14 grid, list и related открывают один viewer по canonical URL. Медиа занимает главную область сверху; ниже находятся компактные действия, теги и связанные материалы, сначала коллекция, затем Same tags. Контекст исходного сохранённого поиска передаётся через URL и Back, без отдельного поясняющего блока; quick-preview и правой панели нет. Category по-прежнему saved query, не дополнительное назначение материала. Все действия старых viewer flows собраны в этом пути, а Back восстанавливает query/type/sort/page/scroll. Viewer учитывает одно открытие через 3 секунды с отменой при раннем уходе; thumbnails/list не создают просмотр. Производные poster/preview assets сохраняются и не являются отдельным UI-режимом.

По просьбе разгрузить кнопки действия собраны в три группы: навигация, настройка изображения и организация. Компоновка сохраняет медиа `80dvh`: под ним слева Back с узнаваемой стрелкой влево с хвостом, рядом Edit и favorite; Previous/position/Next в центре с симметричными одинаковыми chevrons; справа одна иконка `Image tools`. Она открывает панель zoom out/reset/zoom in/rotate, скрытую по умолчанию; управление доступно кликом и клавиатурой, Escape закрывает панель с возвратом focus к trigger, клик снаружи также закрывает её. Следующая строка содержит только теги, Edit/favorite не занимают этот ряд. Выбранный favorite меняет только SVG-звезду — цвет/заливку; selected-рамки, фона и контура у кнопки нет, `aria-pressed` и обычный focus-ring сохраняются. Постоянно видны шесть действий у фото и пять у видео. Компоновка принята по D-16 и сохраняет функции D-12/D-14, контекст, счётчик и video-controls.

Название коллекции не дублируется под тегами. Ниже находится её группа перед `Same tags`; заголовок — только имя коллекции, кликабельное для открытия её страницы, без `In collection` и отдельного `All`. Если коллекция назначена, заголовок виден даже без других материалов в ней; если `collectionId == null`, группы коллекции нет.

Заголовок `Same tags` открывает обычную галерею по AND всех имён тегов материала, новые первыми (`uploadedDesc`), страница 1, без type/collection/подмножества загрузок. Галерея включает текущий материал и материалы с дополнительными тегами. Это отличается от самой related-секции, где сохранено точное совпадение непустого набора tag ID с исключением текущего материала.

Пользователь выбрал **B с простым неинтерактивным текстом**: media-cards и related thumbnails в покое показывают только медиа, без постоянного ряда тегов. Hover или keyboard focus открывает плавающий popup под миниатюрой с переносом выше при нехватке места у нижней границы окна, со всеми тегами через `·`, без chips, ссылок и `+N`; перенос длинного набора допустим. Grid при открытии не меняет размеры/положение карточек, визуальный зазор не прерывает переход указателя в popup, текст не обрезается контейнером или краями окна. Escape закрывает popup без переноса focus. Теги viewer/list остаются кликабельными; Same tags и порядок коллекции сохраняются. [Сравнение A/B/C](tag-layout-options.html) — исторический материал выбора; прежняя рекомендация A не действует. Подробности доступности — в [UX-аудите](../05-ux-ui-audit.md); выбранное поведение входит в D-16.

На главной grid не содержит checkbox/selection/bulk-toolbar, Add/upload shortcut или search-help `?`. Sidebar Uploads остаётся; Add/Choose files доступны только внутри Uploads. Выделение и массовая замена доступны только в list и входят в согласованный целевой UI по D-16. Семь уровней размера миниатюр управляются в grid иконками `+`/`−`: увеличить/уменьшить медиа, меньше/больше колонок, disabled на границах и сохранение настройки. Slider отсутствует; в list controls размера скрыты.

В list колонки расположены как `Media`, `Tags`, `Collection`, `Actions`. В Actions справа находятся Edit media, затем checkbox у правого края. Они видны по hover/focus-within без сдвига строки; opacity-hidden controls доступны Tab и раскрываются при focus, отмеченный checkbox остаётся видимым после hover. Edit media открывает существующий редактор одного материала без viewer/смены route; Cancel сохраняет metadata и возвращает focus к Edit. Grid selection не получает.

Поле запроса и Photos/Videos/Sort/Clear filters находятся в одной рамке search form; Clear filters виден всегда и сохраняет прежнюю reset-семантику. Справа снаружи — `+`/`−` и Grid/List, на той же строке desktop, с допустимым переносом на узкой ширине без overflow. Все controls выполнены в одном icon-style, кнопки 32 px. Общий total найденных материалов расположен в footer под grid/list рядом с пагинацией, не в header; он не равен размеру текущей страницы из 24 записей.

Новые переходы по тегу, категории или коллекции создают собственную выдачу: новые первыми, страница 1, без унаследованных фильтров прежней выдачи; категория дополнительно задаёт свой тип. Back из viewer возвращает исходный query/type/sort/page/scroll.

Sidebar по умолчанию раскрыт. Expand/Collapse sidebar переключает его вручную между полной панелью и rail `72px`, без CSS-автосворачивания. В rail остаются доступные ссылки-иконки Library/Collections/Tags/Categories сверху и Uploads внизу viewport; подписи и бренд скрыты, English title/aria-label и active route сохраняются. Uploads badge компактно показан на иконке и обновляется. Toggle вне aside доступен в обоих состояниях с aria-expanded/aria-controls, preference переживает reload. Контент получает дополнительную ширину без новой header-строки и пересоздания workspace; viewer/playback, ввод и list selection не сбрасываются. Sidebar sticky высотой 100dvh; бренд виден рядом с toggle при раскрытии. Раздел и document title — Categories, canonical `#/categories`, совместимый alias `#/saved-searches`; смысл saved query не меняется.

Согласованные организационные разделы: `Tags` — компактная таблица `Tag`/`Usage count`, `Categories` — `Name`/`Query`/`Items type`. Имена открывают галерею с прежним tag query или category query + type. `Collections` — компактная auto-fill сетка с квадратной cover, min 160 px, gap 12 px и именем 14 px под ней: три коллекции не превращаются в три огромные панели. Описаний и отдельного `Open media` нет; total под каждым разделом считает сущности. Модели, English UI, rail 72 px и viewer/state сохраняются. CRUD в этой итерации не добавляется, неработающих кнопок нет; production-обязательства по управлению сущностями остаются в основной спецификации.

По D-15 Uploads — только текущие незавершённые и ошибочные загрузки, без истории и таймеров X дней. Успех после публикации ready item немедленно убирает строку/входное имя из очереди; ручной Cancel также сразу убирает задачу. Failed/idle/receiving остаются до успешного Retry либо Cancel, в том числе после reload. Успешные и отменённые записи не архивируются; batch исчезает вместе с последней оставшейся задачей. Cleanup готового/отменённого input выполняется отдельно и не возвращает строку в Uploads. Badge сохраняет прежний active count queued/running без failed. Готовое медиа находится в Library; новые upload-history UI, ACK или отдельная history-таблица не добавляются.

Редактор рассчитан на 20–30 тегов и сотни коллекций: selected tag chips + поиск; коллекция — одно searchable single-select поле selected name + chevron + inline clear/`No collection`, без chip и отдельного input. Оба поля локально ищут case-insensitive подстроку в существующих именах; выбор сохраняет ID, коллекция заменяет прежний nullable ID, ввод сам ничего не назначает и не создаёт. ArrowUp/Down перемещают активную option, Enter подтверждает выбор, Escape закрывает popup, Tab переводит focus; Escape/Tab/blur восстанавливают label выбранной draft-коллекции вместо неподтверждённого query. Cancel не меняет metadata, failed Save оставляет draft и ввод тегов, pending Save блокирует изменения и повтор. Внешний responsive bounding box модального окна не меняется при focus, typing, clear, pick и 0/350 результатах. Popup расположен поверх формы вне layout flow, имеет собственную прокрутку, max-height 220px с viewport clamp/flip вверх, не обрезается overflow диалога и не прокручивает вложенную форму/страницу. Footer доступен в невысоком окне. На Collections `Search collections` live фильтрует полный справочник по буквальной подстроке; clear/no-match, footer shown/total и URL `#/collections?search=…` сохраняют фильтр при Back/reload, компактная сетка остаётся. Стандартные 8 тегов/3 коллекции не меняются; 30/350 — отдельная QA-инъекция, не жёсткий лимит и не новый API или изменение D-15.

## Открыть и попробовать

Откройте [index.html](index.html) в браузере. Если просмотрщик репозитория показывает исходный код, скачайте этот файл и откройте его локально. Все изображения, видео, стили и код встроены; сервер, Docker и подключение к интернету не нужны. Визуальная debug-кнопка сброса удалена. Для исследовательского сброса в DevTools остаётся `TFDemo.reset()`; это не функция продукта.

В библиотеке 426 синтетических записей, восемь тегов, три коллекции и три сохраненных поиска. Изменения метаданных, созданные медиа, только pending/error задачи и предпочтения сохраняются в localStorage браузера, если браузер разрешает его для локального файла. Эти данные принадлежат только макету.

1. Введите `mountains && !city`, нажмите Enter, перейдите на следующую страницу. Откройте материал, измените теги и коллекцию, сохраните и вернитесь к результатам. Проверьте сохранение запроса, страницы и места прокрутки.
2. Откройте редактор еще раз, измените поля и нажмите `Cancel`. Теги и коллекция должны остаться прежними. Для просмотра ошибки сохранения выполните в DevTools `TFDemo.debug.failNextSave()` перед нажатием `Save`: данные не изменятся, введенное останется в форме для повтора.
3. Откройте `Uploads`: видны только передаваемые, обрабатываемые и ошибочные задачи. Повторите ошибку либо отмените её; failed остаётся без TTL, ready/cancel исчезают сразу. Перейдите в Library и обратно: незавершённые/ошибочные задачи сохраняются, успешные медиа находятся в Library без истории Uploads.
4. Попробуйте независимые иконки Image и Video: только одна фильтрует соответствующий тип, обе либо ни одной означают all, сохраняя состояние обеих кнопок. Откройте Sort и переключите все семь пунктов; видимый select не нужен. Из grid, list и related откройте один viewer, проверьте расположение тегов/коллекции ниже медиа, панель `Image tools` для zoom/rotate фото, видео controls/горячие клавиши и Back; во время ввода в форму эти клавиши не управляют просмотром.

## Реализованный целевой интерфейс

| Поверхность | Доступные взаимодействия |
| --- | --- |
| Библиотека | Поиск по точным именам тегов с `&&`, `||`, `!`, скобками; ошибка выражения; пустой результат; тип; семь сортировок; страницы по 24 записи; сетка/список; размер миниатюр `+`/`−` только grid; выделение текущей страницы только list |
| Просмотр и редактор | Один viewer из grid/list/related; медиа сверху, теги/коллекция ниже; предыдущий/следующий в контексте и Back к выдаче; zoom/rotate фото; настоящее короткое видео; favorite; теги и одна коллекция как общий draft; отмена, pending, ошибка и повтор сохранения; массовая замена для выделенных в list |
| Загрузки | Pending/error очередь, этапы передачи/обработки, Retry/Cancel, исчезновение ready/cancel без истории; выбор photo/video и демонстрационный пакет, без age-based expiry |

Разделы тегов, коллекций и категорий показывают точки входа к выдаче; поиск коллекций и массовый редактор в list входят в согласованный baseline. CRUD организационных сущностей в макете не реализован, но остаётся обязательством production-версии. Макет задаёт интерфейс и реализованные взаимодействия, а полный функциональный контракт, включая API-only возможности исходного приложения, задают документы 01–07. Отсутствие функции в демонстрации не отменяет её паритет.

## Границы имитации

Загрузка и сохранение моделируются внутри браузера. При выборе файла используются только временное входное имя, размер и MIME-тип; его содержимое не читается, не отправляется и не конвертируется. В библиотеке появится демонстрационное медиа без пользовательского названия. Имя входа помогает сопоставить только передачу или ошибку в очереди, а готовый результат показывается без него. Проценты и processing — сценарий интерфейса, а не измерение передачи или FFmpeg. Атомарное изменение локального состояния не доказывает транзакционность будущего API.

LocalStorage, hash encoding маршрутов, debug/reset API, задержки и фиксированная последовательность Random не являются требованиями к реализации. Демонстрационный parser допускает некоторые выражения шире целевой грамматики; продукционный поиск, проверки синтаксиса и новый Random при новом поиске/refresh определяются документом 02. Ни один такой допуск не расширяет язык поиска автоматически. Обложки, порядок/группировка статистики тегов и четырёхкарточные related-примеры используют упрощённые fixture-выборки; production сохраняет правила данных и полную достижимость результатов из 02, включая oldest cover, глобальную статистику и пагинацию.

Нет backend, S3, реальных сетевых ошибок, лимитов диска, конкурентных изменений, HTTP 412, восстановления upload-сессий или проверки 100 GB. Удаление, legacy-форматы и остальные возможности полного продукта должны реализовываться по основной спецификации. Макет не является переносом приложения на React: использован небольшой автономный HTML/CSS/JavaScript, чтобы проверить интерфейс до реализации выбранного стека.

Фотографии — публичные stock-изображения, классификация вымышлена. У media-записей нет пользовательских названий. Все video-записи используют один настоящий короткий беззвучный тестовый MP4; декоративные фото-постеры не являются кадрами этого ролика. Авторы, условия использования и hashes находятся в [источниках медиа](assets/SOURCES.md).

Исходники: `index.template.html`, `styles.css`, `fixtures.js`, `app.js`. Они и `build.mjs` зафиксированы в [паспорте baseline](accepted-baseline.json); пересборка текущих исходников должна воспроизводить тот же SHA-256 `index.html`. Будущие изменения согласованного интерфейса отражаются в спецификации и новой версии baseline. Генерируемый `index.html` следует пересобирать после изменения исходников. Изображения и ролик уже находятся в `fixtures.js` как data URI; исходные файлы сохранены для воспроизводимости.

Для повторения автоматического браузерного прогона установите Playwright и его Chromium в отдельное окружение и передайте абсолютный путь к модулю:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright node docs/rewrite/prototype/qa/check.mjs
```

Среда должна содержать системные библиотеки и шрифты для Chromium. Скрипт обновляет отчет и скриншоты выбранных сценариев; их список находится в отчёте. Без `TF_QA_ONLY` выполняются все сценарии. Это приемка исследовательского макета, а не будущий production test suite.
