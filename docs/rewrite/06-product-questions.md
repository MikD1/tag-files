# Принятые продуктовые решения

Этот реестр фиксирует ответы владельца продукта и заменяет первоначальный список из 30 вопросов. Решения D-01…D-16 и одобренный 14 ноября 2026 макет v27 задают целевой UI/поведение; [функциональный реестр F-01…F-38](01-current-behavior.md) сохраняет исторические факты и обязательный паритет остальных возможностей. Новые предложения за пределами принятого baseline остаются отдельным backlog.

## Подтверждённые решения

| ID | Решение | Следствие для новой версии |
| --- | --- | --- |
| D-01 | Один пользователь, браузер на том же современном Mac, запуск через Docker Desktop | Локальное приложение с одним origin; LAN, аккаунты и многопользовательская модель не требуются |
| D-02 | Новые загрузки — только фото и видео | Другие типы отклоняются с понятной ошибкой; исторические Unknown/Text/Audio и их метаданные при миграции сохраняются |
| D-03 | Дополнительные оригиналы не хранятся; загрузка и обработка автоматические | В библиотеке остаётся готовая рабочая версия и preview. Входной файл временно нужен для обработки/retry; он удаляется после проверки и надёжной публикации результата. Отдельного подтверждения конвертации или выбора архивирования нет |
| D-04 | Исходное разрешение фото и видео сохраняется | Основная рабочая копия не уменьшается и не увеличивается; уменьшение допустимо для preview. Сохраняются пропорции и правильная ориентация |
| D-05 | Удаление элемента окончательное | Корзина, период восстановления и Undo удаления не входят в v1. Отказ от подтверждений в обсуждении относился к загрузке; отдельное решение о подтверждении ручного UI-удаления не принималось |
| D-06 | Коллекции — аналог папок; у элемента одна коллекция, множественная классификация выполняется тегами | Связь item → collection nullable 1:N сохраняется. Вложенность и несколько коллекций на элемент не добавляются; физическое расположение файлов от названий коллекций не зависит |
| D-07 | Переименование тега должно переименовать его в фильтрах категорий и сохранить найденные элементы | Ссылки в AST остаются по tag ID, отображаемое выражение и актуальный текст фильтра обновляются при rename; исторический исходник миграции хранится отдельно |
| D-08 | Файлами библиотеки управляет только Tag Files | Finder-доступ, редактирование файлов другими программами и соответствие коллекций каталогам на Mac не требуются; допускается внутреннее хранилище в Docker volume |
| D-09 | Миграция, export/import и backup/restore вынесены из основного сервиса | Перенос выполняет отдельный одноразовый скрипт. Бэкапы организует пользователь; отдельные скрипт и инструкция допустимы. В основном сервисе нет соответствующих CLI-команд, API, UI и планировщика |
| D-10 | При переходе допустимы остановка старой версии и отдельная новая копия библиотеки | Offline migration, read-only источник, возобновляемое копирование и проверка до cutover; временно хранятся обе копии, требуется ещё примерно 100 GB и вычисленный запас |
| D-11 | Мелкие детали не требуют отдельных продуктовых вопросов | Текущее полезное поведение — default; недостатки прототипа не копируются. Технические лимиты и алгоритмы остаются решением реализации с проверками |
| D-12 | Минималистичная медиатека с акцентом на контент и теги; пользовательских названий у материалов нет | В галерее и просмотре нет имён файлов, вымышленных заголовков, технических сведений, описаний и постоянных обучающих текстов. Основное содержимое — фото/видео и теги; навигация, favorite, коллекция и редактирование доступны компактно. Справка открывается по запросу, ошибки появляются по ситуации. Входное имя нужно только на время загрузки/разбора результата и не становится названием готового материала |
| D-13 | Интерфейс и весь демонстрационный контент на английском, как в legacy; фильтры типа, сортировка и добавление представлены иконками | Английские labels, accessible names, tooltips, ошибки, пустые состояния и помощь; нет нового переключателя языка. Два независимых Image/Video icon-toggle сохраняют текущие четыре состояния. Sort открывает меню из семи пунктов с иконками и English labels; добавление — icon-only только в Uploads, без дубликата в галерее. Демо-теги, коллекции и сохранённые поиски на английском; реальные пользовательские данные не переводятся |
| D-14 | Один режим просмотра с главным акцентом на медиа; теги, коллекция и уместный контекст ниже контента, как в legacy | Из grid/list/related открывается один viewer с canonical URL, без отдельного quick-preview и правой информационной панели. Сохраняются Back с query/type/sort/scroll, prev/next, zoom/rotate, video controls, favorite, редактирование тегов/коллекции и связанные материалы. Один логический просмотр учитывается через 3 секунды, миниатюры/списки не учитываются |
| D-15 | Uploads хранит только незавершённые и ошибочные загрузки, без истории и TTL | Решение от 14 ноября 2026: успешная запись исчезает сразу после проверенного primary и ready commit; отменённая — при принятии cancel. Ошибки, idle/receiving и необходимые входы сохраняются до успешного retry или ручной отмены, независимо от возраста. Cleanup продолжается отдельно и не удерживает строку Uploads |
| D-16 | Текущий макет v27 и его пользовательское поведение одобрены как целевые | Решение от 14 ноября 2026: «Все ок. Давай фиксировать текущий макет и все поведение как целевое». Компоновка и взаимодействия v27, включая массовую атомарную замену tags/collection только в list, становятся обязательным baseline UI. Исторические альтернативы не действуют; имитация backend и отсутствие отдельных CRUD/API функций не сокращают production scope |

Наличие одной рабочей копии не требует повторного перекодирования уже совместимого файла ради самого перекодирования. Видео использует текущий выходной профиль MP4 H.264/AAC. Для фото сохраняется действующий подход: пригодный для просмотра формат может пройти без изменения байтов; если преобразование нужно, результат становится единственной рабочей копией с тем же разрешением. Хранить рядом загруженный input как дополнительный архив не нужно. Качество не увеличивается автоматически из-за смены формата.

D-12 уточняет пользовательский интерфейс и исправляет допущение первого UX-макета: его вымышленные `title`/`filename` не являются продуктовой моделью. В текущем `LibraryItem` нет Title или исходного имени; `FileName` — внутренний ключ объекта. В новой модели item также нет `title`, `displayName` или `originalFilename`. UUID, object keys, MIME, размеры, длительность, timestamps и другие служебные данные остаются допустимыми для backend и диагностики. Длительность и controls воспроизведения относятся к просмотру видео и могут быть видимыми. Legacy description и другие сохранённые данные продолжают переноситься и быть доступными через совместимые операции; отсутствие этих полей на обычных экранах не разрешает их удаление.

D-13 относится к системному тексту продукта и синтетическому демо-контенту; документация исследования остаётся на русском. Это не ограничивает Unicode/регистр пользовательских тегов, названий коллекций и запросов, не требует автоматического перевода и не меняет миграцию настоящих данных. У icon-only controls остаются английские accessible name/tooltip, focus и keyboard-доступ, у toggle — `aria-pressed`, у sort trigger — expanded state и выбранный пункт меню. Подписи в открытом меню не захламляют обычный вид галереи.

D-14 принят 12 ноября 2026 и осознанно меняет прежнее требование сохранять два legacy viewer flows: их действия объединяются в один экран, факты старого приложения в F-реестре остаются неизменными. Слово «категория» в обсуждении расположения означает уместный вторичный контекст; сущность Category остаётся сохранённым query и не становится новым назначением item. Под медиа находятся теги, компактные controls и связь с одной коллекцией; контекст сохранённого поиска сохраняется в URL/Back при соответствующем origin, без обязательного постоянного label. Технические сведения и description по D-12 не возвращаются. Thumbnail/poster/preview assets для сетки и обработки сохраняются: это производные медиа, а не второй UI просмотра. Единый viewer сохраняет правило 3 секунд и идемпотентный event ID; старое различие quick-preview/detail для счётчика больше не применяется, новые условия видимости вкладки/playback не вводятся.

D-15 отменяет прежние рекомендации истории batch/terminal results и Session TTL 7 дней. Uploads — очередь pending/error, не журнал: отдельной history-таблицы и подтверждения ознакомления нет. При ready/cancel строка убирается немедленно; очистка owned incoming/MPU/candidates выполняется отдельными durable receipts/jobs до завершения, без календарного срока и без удаления уже опубликованного item. Служебный `items.upload_id` (nullable UNIQUE; legacy NULL) позволяет найти готовый материал после удаления upload session и безопасно повторить GET/Complete без истории. Общий operation_results TTL для идемпотентности HTTP-команд, navigation TTL и внешняя политика резервных копий не отменяются: это не retention очереди Uploads.

D-16 фиксирует [макет v27](prototype/README.md) с [паспортом принятой версии](prototype/accepted-baseline.json); это одобрение UI/взаимодействий, не заявление о готовой production-реализации или пройденной полной приёмке. В baseline входят gallery/search/icons/footer, sidebar/rail, один viewer, hover-теги, компактные Tags/Categories/Collections, локальный Search collections, стабильный editor с chips и одним searchable полем коллекции, атомарный single/bulk Save и pending/error Uploads. Tag/category/collection links создают свежий контекст UploadedDesc/page 1; Back viewer сохраняет исходный sort/page. Bulk ограничен выбором видимых строк list: полный replace обоих полей, не add/remove и не все страницы. Debug/reset/demo batch, таймеры, browser-only metadata, синтетические данные и упрощения parser/seed не являются продуктовой архитектурой. Production grammar, Random, API-only операции, upload collection assignment, CRUD и надёжность сохраняются по спецификации/F-реестру, даже если макет их не исполняет.

## Целевое поведение и defaults

| Область | Правило для спецификации |
| --- | --- |
| Идентичность тегов | Точное регистрозависимое сравнение; регистр и Unicode не нормализуются. Существующее разрешение одинаковых имён сохраняется; автоматического слияния и нового UNIQUE(name) нет |
| Названия и описание | Имена есть у тегов, категорий и коллекций, у медиа пользовательского названия нет. Тег 1…50, буквы/цифры/дефис; категория/коллекция 1…200; сохранённое description nullable до 150 переносится, но не выводится в обычном просмотре. Новый редактор description не входит в обязательный паритет |
| Назначение тегов | Replace полного набора; bulk API сохраняется. По D-16 list selection и общая атомарная замена tags/collection обязательны; add/remove и выбор всех совпадений через страницы остаются backlog |
| Коллекции | Плоский список, 0/1 коллекция на элемент; состав новые первыми, автоматическая обложка из самого старого элемента. Удаление организационной группы сохраняет элементы и снимает членство |
| Категории | Именованный tag query и необязательный тип; по D-16 клик имени создаёт новую выдачу UploadedDesc/page 1. Tag/collection links создают такие же новые contexts; Back viewer сохраняет origin sort/page. Rename тега выполняет D-07 |
| Поиск | `&&`, `\|\|`, `!tag`, скобки и точные имена; тип пересекается с tag query. Некорректный ввод получает явную ошибку; потеря символов старым parser не является требованием |
| Статистика | Глобальная по всей библиотеке, с нулевыми использованиями, группировкой по имени и сортировкой count DESC/name ASC |
| Сортировки | Все семь текущих режимов; NULL duration при ASC впереди, при DESC в конце. Стабильный ID tie-breaker определяет ранее неоговорённые равенства |
| Random | Новая случайная выдача при новом поиске/refresh. Внутри одной выдачи технический контекст удерживает порядок для страниц и prev/next |
| Просмотр | По D-14 единый viewer отправляет один логический view через 3 секунды; уход раньше отменяет отправку. Повтор effect/retry того же открытия не удваивает event. Миниатюры и выдача не создают просмотр; новых условий видимости вкладки или фактического playback нет |
| Похожие | Строго тот же непустой набор tag ID, текущий элемент исключён, новые первыми |
| Избранное | Флаг элемента и индикация; новая отдельная страница/фильтр — UX-предложение |
| Представление | Grid/list открывают один viewer по D-14; zoom/rotate изображения и существующие video hotkeys сохраняются. Медиа сверху, теги/коллекция/контекст ниже; sidebar, view и семь уровней плотности остаются |
| Повторная загрузка | Независимый новый item; hash применяется для целостности, автоматической дедупликации нет |
| API и ссылки | Функциональные возможности API-only сохраняются; физические S3 пути и прежние JSON-маршруты не являются обязательными. Числовые ID и `/content/:id` сохраняются |

Надёжная очередь, согласованность S3/SQLite, наблюдаемые ошибки, полная достижимость выдачи и безопасный повтор HTTP-команд — технические требования переписывания. Они не расширяют продукт до управления бэкапами или произвольными файлами.

## Условия разработки и стек приложения

Владелец уточнил, что новую версию разрабатывают **AI-агенты**. Это подтверждённое условие разработки, а не новая функция приложения. Опыт человеческой команды в C#/Angular не используется как основной аргумент выбора.

В [ADR APP-01](09-application-stack-decision.md) рекомендуется **Go + React SPA**: стандартный HTTP, SQLite с явным SQL и генерацией типов, общий OpenAPI, закреплённый набор frontend-библиотек. .NET 10 + React и Node/Fastify + React рассмотрены как самостоятельные альтернативы. Выбор остаётся технической рекомендацией автора исследования и не выдаётся за отдельное подтверждение владельцем конкретного языка.

Для работы агентов фиксируются границы модулей, источник API/SQL-контрактов, воспроизводимая генерация и обязательные проверки паритета, streaming и recovery. Утверждений о превосходстве конкретного языка для всех AI-моделей или измеренном ускорении приложения нет. D-01…D-16, внешний migration/backup и выбранное S3-хранилище сохраняются.

## Техническое решение по хранению

По поручению сравнить S3-варианты для целевой архитектуры выбран **SeaweedFS 4.53: `weed mini`, embedded LevelDB2, сохранённый глобальный fsync rule**. Это рекомендация исследования, зафиксированная как [ADR S3-01](08-s3-storage-decision.md), а не дополнительный ответ владельца продукта с D-ID. Она заменяет первоначальный вариант прямого хранения файлов приложением.

Поставка состоит из app и storage в одном Compose deployment. SQLite и jobs остаются в app; storage имеет отдельный Linux named volume, доступен только внутри Compose. Браузер использует один origin приложения. Загрузка опирается на native S3 multipart через app proxy; исходный input временно сохраняется в S3 до проверки рабочей копии и commit БД. Свой механизм физического распределения по UUID-префиксам не вводится. Выбор должен пройти обязательную техническую приёмку; другие движки не включаются в v1 как автоматический fallback.

Это не меняет D-03/D-09: дополнительные оригиналы не архивируются, migration/backup/restore остаются внешними скриптами. Для cold backup останавливаются оба сервиса и сохраняются весь Seaweed state с metadata/chunks/config и SQLite; основной сервис не получает backup API/UI. Runtime-проверка выбранного хранилища на Mac и rehearsal восстановления обязательны до переноса настоящих данных.

## Что нужно проверить перед реальным переносом

Это проверки отдельного скрипта и runbook, а не новый вопросник владельцу продукта:

- Установить версию схемы, действительные размеры, наличие всех media, orphan/duplicate links, старые durations и категорийные выражения по read-only snapshot.
- Рассчитать свободное место Mac и Docker VM для новой копии, staging и запаса; измерить copy/verify на pilot и назначить окно остановки. Согласие на две копии не означает, что место уже измерено или выделено.
- Сделать независимый backup средствами пользователя, проверить восстановление и только затем выполнять финальный перенос. Основной сервис в этом не участвует.
- Уточнять с пользователем только обнаруженную невосстановимую потерю/неоднозначность конкретных данных или необходимость изменить подтверждённую модель. Нельзя молча исправлять её удалением записей, слиянием тегов либо потерей доступных файлов.

Расписание бэкапов, их retention, RPO/RTO и расположение носителей выбирает пользователь вне Tag Files. Сценарий первой миграции и требования к внешним скриптам описаны в [миграции и эксплуатации](04-migration-and-operations.md).

## Отдельный backlog

Полнотекстовый поиск, Favorites view, bulk add/remove и выбор всех совпадений через страницы, создание тегов внутри формы, ручные cover/order, дополнительные viewers, корзина, watched folders и удалённый доступ не включаются в rewrite по умолчанию. Selection текущей страницы и атомарный bulk replace tags/collection в list уже входят в D-16; это не backlog. [UX-аудит](05-ux-ui-audit.md) сохраняет обоснование возможных улучшений; он не изменяет D-01…D-16.

Прежние Q-03/Q-04/Q-05/Q-08/Q-11/Q-12/Q-25 закрыты решениями выше. Остальные прежние вопросы о деталях заменены defaults и техническими проверками. Для начала реализации не требуется отвечать на первоначальный список P0.
