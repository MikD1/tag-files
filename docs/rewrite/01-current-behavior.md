# Текущее поведение и функциональный контракт для переписывания

Дата исследования: 10 ноября 2026 года. Основание — исходники backend, Angular и существующих тестов в этом репозитории. Приложение и Docker не запускались, пользовательские файлы и базы не открывались. Документ описывает реализованные возможности; успешное выполнение каждого сценария на живой установке здесь не утверждается.

## Как читать документ

**Факт** означает, что поведение следует из кода или явно проверяется существующим тестом. **Приемка rewrite** — проверка сохранения полезной возможности при новой реализации; это не требование копировать ошибки, сетевые адреса, библиотеки или устройство кода. **Вопрос** означает, что имеющихся исходников недостаточно для продуктового решения.

Обозначения доступности: **UI + API** — есть достижимый пользовательский сценарий и backend; **API** — публичный endpoint есть, но достижимого элемента UI нет; **UI** — поведение браузера. Метод доменной модели или репозитория сам по себе не считается доступной функцией продукта. ID `F-01`…`F-38` служат устойчивыми ссылками из остальных документов.

### Подтвержденные требования rewrite

Один пользователь работает в браузере на том же современном Mac с Docker Desktop. Несколько тысяч материалов и около 100 GB существующих медиа переносятся в новую библиотеку. Предложение по платформе контейнера — основная `linux/arm64` для Apple Silicon и вторичная `linux/amd64`, уже присутствующая в поставке прототипа; конкретную модель Mac пользователь не называл. Мобильный доступ, LAN и аккаунты не требуются для согласованного базового сценария. В текущем коде также нет аккаунтов, ролей и разграничения библиотек; это факт реализации, отдельно от требований.

Уточнение целевой архитектуры от 11 ноября 2026: два контейнера — modular monolith приложения с SQLite и SeaweedFS 4.53 в режиме `mini`, с embedded LevelDB2 и глобальным правилом fsync для всех путей. Браузер обращается только к локальному origin приложения; S3 остается внутренним. Upload потоково проксируется приложением через native S3 MPU в durable incoming. Это принятое устройство rewrite, описанное в [08-s3-storage-decision.md](08-s3-storage-decision.md), а не характеристика текущего прототипа.

| Область | Подтвержденное решение |
| --- | --- |
| Новая загрузка | Только фото и видео. Исходное разрешение сохраняется; библиотека хранит готовую версию и preview, без дополнительного original. Конвертация, сохранение, проверка результата и удаление временного upload-исходника выполняются автоматически: для пользователя это одна операция Upload без промежуточных подтверждений. Источник удаляется только после PUT canonical, полного GET с совпавшим хешем и commit ready в SQLite. Прогресс и ошибка остаются видимыми. |
| Старые данные | Уже существующие Unknown/Text/Audio, их файлы, metadata и сохраненные фильтры не теряются при переносе. Ограничение новых загрузок фото/видео не разрешает отбрасывать legacy-данные и не добавляет работающие audio/text viewers. |
| Удаление материала | Окончательное, без корзины и восстановления через Undo. Отказ от подтверждений относится к автоматическим этапам Upload; он не задает поведение будущей кнопки удаления материала. Подтверждение перед таким UI-действием остается UX-предложением. |
| Классификация | Материал принадлежит нулю или одной коллекции, похожей на папку; несколько тегов дают независимую классификацию. Сохраняется плоская структура, вложенность не вводится. Категории остаются сохраненными фильтрами. Удаление коллекции убирает группу и снимает членство, материалы сохраняются. |
| Переименование тега | Обновляет связанные сохраненные фильтры категорий так, чтобы они находили тот же набор материалов. Связи с материалами сохраняются. |
| Владение библиотекой | Библиотекой управляет TagFiles; интеграция с Finder не требуется. |
| Перенос и резервирование | Migration/import/export и backup/restore — отдельные инструменты вне кода основного сервиса: без встроенных CLI/API/UI и scheduler. Миграция — отдельный одноразовый скрипт. Резервное копирование обеспечивает пользователь; возможны отдельный скрипт и инструкция. |
| Условия переноса | Допустим полный offline-copy с остановкой сервиса; доступно место еще примерно под 100 GB копии. Это условие операции, а не функция основного приложения. |
| Остальные детали | Сохраняется полезное текущее поведение без повторного опроса о мелких решениях. Технические ограничения и дефекты не становятся требованиями. Новые UX-возможности остаются отдельными предложениями. |

Решения собраны в [06-product-questions.md](06-product-questions.md). Следующий реестр и описания исходников фиксируют прототип; их прежние указания на требующие решения вопросы читаются с учетом подтвержденных требований выше.

## Позиционирование и сущности

По реализованным сценариям это персональная медиатека с ручной разметкой тегами, логическими запросами по тегам, сохраненными фильтрами и явными коллекциями. Основные средства просмотра рассчитаны на изображения и видео. Это вывод о назначении по коду, а не найденная в репозитории утвержденная продуктовая спецификация.

| Сущность | Текущее значение и границы |
| --- | --- |
| Элемент медиатеки | Одна сохраненная запись, один объект контента, необязательная миниатюра, набор тегов, необязательная единственная коллекция, признак избранного, счетчик и время последнего просмотра. |
| Тег | Запись справочника с ID и именем; связь с элементами многие-ко-многим. |
| Категория | Именованный сохраненный фильтр: строка `TagQuery` и необязательный `ItemsType`. Членство элементов не хранится. |
| Коллекция | Именованная группа с явным членством через `LibraryItem.CollectionId`; это не сохраненный запрос. |
| Обрабатываемый файл | Запись отдельного жизненного цикла импорта с исходным именем, внутренним именем, типом, статусом и необязательным ID коллекции. Не является самим элементом медиатеки. |

Источники: [модель элемента][M-item], [тег][M-tag], [категория][M-category], [коллекция][M-collection], [обрабатываемый файл][M-processing].

## Точная семантика поиска

### Контракт запроса и результата

`POST /api/library/search` принимает `tagQuery: string|null`, `itemType: FileType|null`, `pageIndex: int`, `pageSize: int`, `sortBy: SortType`. По умолчанию сортировка `UploadedDesc`. Ответ содержит `items`, `totalItems`, `pageIndex`, `totalPages`. Страницы нумеруются **с 1**, смещение `(pageIndex - 1) * pageSize`, число страниц — округление `totalItems/pageSize` вверх. На пустой корректной выдаче `totalPages = 0`. UI не предлагает следующую страницу и запрашивает `1, 300`. В handler нет отдельной проверки положительности номера/размера и максимального размера; поведение некорректных параметров не является обязательством rewrite. [Контракт][DTO-search], [handler][H-search], [пагинация][BE-pagination], [тест пагинации][T-pagination], [UI][UI-search].

Фильтры соединены пересечением: `(условие tagQuery) AND (FileType == itemType)`. `null`, пустая и whitespace-only строка не добавляют условие по тегам. `itemType = null` пропускает все типы, в том числе `Unknown`, а не только Image/Video. На уровне backend возможен любой член enum. Переключатели UI кодируют это так:

| Image | Video | Отправляемый `itemType` |
| --- | --- | --- |
| выкл. | выкл. | `null` — все типы |
| вкл. | выкл. | `Image` |
| выкл. | вкл. | `Video` |
| вкл. | вкл. | `null` — все типы |

Это не фильтр «объединение только image и video»: обе кнопки включены также допускают `Unknown`. Нет фильтров по имени файла, описанию, дате, ID коллекции, избранному, последнему просмотру, диапазону длительности или количеству просмотров. Текстовое содержимое файлов не индексируется.

### Язык тегов и граница корректного ввода

Текущий `TagQueryConverter` не строит AST и не валидирует всю исходную строку. Он последовательно выделяет regex-токены `(!)?([a-zA-Z0-9\-]+)|([()])|(&&)|(\|\|)` и склеивает строку выражения для System.Linq.Dynamic.Core. Тег `a` превращается в `Tags.Any(Name=="a")`, `!a` — в отрицание этого условия. Остальные распознанные символы переносятся как есть. [Конвертер][BE-parser].

Корректное используемое подмножество языка:

| Запись | Значение |
| --- | --- |
| `a` | Есть тег с точным именем `a`. Это не подстрока и не wildcard. |
| `!a` | Тега `a` нет; может совпасть элемент вообще без тегов. |
| `a && b` | Присутствуют оба тега. Другие теги допустимы. |
| `a \|\| b` | Присутствует хотя бы один из тегов. |
| `(a \|\| b) && !c` | Скобки группируют выражение; `c` исключает совпадение. |
| `a \|\| b && c` | Выражение передается Dynamic LINQ, где AND имеет приоритет над OR; явные скобки предпочтительны для приемочных примеров. |

Регистр не нормализуется. Имена в условии сопоставляются через equality с `Tag.Name`; при текущей SQLite-схеме без заданной иной collation это регистрозависимое точное сопоставление. Регистр подсказок Angular, где используется `toLowerCase().includes()`, не меняет backend-семантику поиска. Неизвестное имя — допустимый предикат без совпадений; отрицание такого имени пропускает все элементы.

NOT в корректном подмножестве прикреплен непосредственно к имени: `!a`. Общая операция `!(...)` данным конвертером не реализована: отдельный `!` перед скобкой не попадает в результат. Аналогично нет словесных `AND/OR/NOT`, неявного AND между словами, кавычек для фраз и экранирования имен. Пробелы между корректными токенами игнорируются, однако разрыв `! a` теряет отрицание. Это ограничения существующего ввода, а не рекомендация так проектировать новый язык.

Другие символы не отвергаются как самостоятельная синтаксическая ошибка, а могут быть пропущены или разбить имя на части; затем возможна ошибка вычисления Dynamic LINQ. Например, Unicode-имя, допускаемое доменной моделью тега, не является целым токеном этого regex. **Не нужно воспроизводить в rewrite молчаливую потерю символов, отрицания или внутренние сообщения парсера.** Для корректного подмножества результат должен сохраниться; для остальных строк требуется явное продуктовое правило.

Контрольный набор для F-08/F-09: A=`Image {a,b}`, B=`Video {a,c}`, C=`Image {a,c,d}`, D=`Image {}`, E=`Video {b}`.

| Запрос | Тип | Ожидаемые элементы без учета сортировки |
| --- | --- | --- |
| `a && (b \|\| c) && !d` | все | A, B |
| `a \|\| c` | Image | A, C |
| `!a` | все | D, E |
| `a && missing` | все | пусто |
| `!missing` | все | A, B, C, D, E |
| пустой | Image | A, C, D |

Существующие тесты подтверждают преобразование корректных выражений, совместную фильтрацию и алфавитный порядок тегов в DTO; отдельно не проверяют все правила приоритета, регистр, Unicode и некорректный ввод. [Тесты парсера][T-parser], [тесты поиска][T-search].

### Сортировки

| Значение API | Поле и направление |
| --- | --- |
| `UploadedDesc` | `UploadedOn DESC`; режим по умолчанию и fallback handler для прочего значения |
| `UploadedAsc` | `UploadedOn ASC` |
| `VideoDurationDesc` / `VideoDurationAsc` | nullable `VideoDuration` по убыванию/возрастанию; не включает автоматически фильтр Video |
| `ViewCountDesc` / `ViewCountAsc` | `ViewCount` по убыванию/возрастанию |
| `Random` | новый `ORDER BY Random()` при каждом запросе |

В SQLite длительность сохраняется как ticks через value converter. При ASC `NULL` идет перед ненулевыми значениями, при DESC — после; это следствие текущего хранилища, не подтвержденное отдельным тестом смешанных типов. Ни у одной сортировки нет дополнительного ID-критерия при равных значениях. Random не имеет seed или зафиксированной сессии, поэтому разные запросы страниц не образуют стабильную перестановку и могут повторять/пропускать элементы между страницами. Сохранить возможность случайного просмотра необходимо; выбрать стабильность страниц и tie-breaker следует явно. [Handler][H-search], [модель хранения][BE-db], [тесты сортировок][T-sorting].

## Разметка, категории, коллекции и рекомендации

### Теги

Имя тега имеет длину 1…50 и состоит из `char.IsLetterOrDigit` либо `-`; на уровне модели это включает Unicode-буквы/цифры. Нет trim, приведения регистра, синонимов или иерархии. Даже `-` и `---` допустимы и отмечены в тесте. Уникальный индекс имени не настроен. Политику дублей и регистра нельзя восстановить как однозначное продуктовое решение только по текущей модели. [Tag][M-tag], [тест][T-tag-model], [DbContext][BE-db].

`AssignTags` сначала загружает все запрошенные элементы и существующие теги, сравнивает их количество с длиной входных списков, затем делает `Clear()` и `AddRange()`, сохраняя результат один раз. Это полная **замена**, не добавление к текущим тегам. Пустой список тегов снимает все теги. Повторяющиеся ID/имена во входных списках могут нарушить проверку количества; это не отдельная полезная возможность. DTO сортирует теги по имени. UI сохраняет теги и изменение коллекции двумя последовательными запросами, то есть целая операция модального окна не является одной транзакцией. [Handler][H-tags], [DTO][DTO-item], [Edit][UI-edit].

Переименование меняет имя существующего ID, поэтому связи с медиа сохраняются. Категории хранят запрос текстом, автоматического переписывания имен в этих строках нет. `ITagsRepository.DeleteTag` существует и тестируется как метод репозитория, но `DELETE /api/tags/...` отсутствует; доступной функции удаления тега продукт сейчас не предоставляет. [Controller][BE-tags], [repository][BE-tags-repo].

Статистика группирует записи по имени, считает связи с элементами и сортирует `UsageCount DESC, TagName ASC`; LEFT JOIN сохраняет неиспользуемые имена с нулем. Это число элементов с тегом, а не просмотры и не только текущая поисковая выборка. Если имеются дубли одинакового имени, статистика объединяет их, тогда как операции по имени не задают явного разрешения неоднозначности. [Handler][H-tag-stats], [тест][T-tag-stats].

### Категории

Имя категории имеет длину 1…200; `TagQuery` и `ItemsType` необязательны. На сохранении фильтр не разбирается и не проверяется. В `PUT /api/categories/{id}` `Name = null` означает оставить имя, но значения `TagQuery` и `ItemsType` всегда присваиваются, в том числе `null`: это не полностью частичное обновление. Категория не фиксирует сортировку, размер страницы или результат в момент создания. [Модель][M-category], [controller][BE-categories].

В редакторе типов категории перечислены все значения FileType, но применение в UI выделяет только Image и Video; любое другое значение превращается в отсутствие ограничения. Это граница между сохраненной моделью и достижимой семантикой UI, которую нужно согласовать, а не закреплять как полезную особенность. Сортировка при применении категории остается выбранной ранее. [Редактор][UI-category-edit], [применение][UI-categories].

### Коллекции и «похожие»

Имя коллекции имеет длину 1…200. Элемент может принадлежать нулю или одной коллекции; подборки с множественным членством не реализованы. `assign-to-collection` требует непустой список элементов; HTTP controller трактует `collectionId = 0` как `null`, handler проверяет существование ненулевой цели. ID коллекции в запросе **инициации загрузки** такой же проверкой не проходит. [Модель][M-collection], [controller][BE-library], [handler][H-assign-collection], [инициация][H-upload].

Коллекция возвращает все элементы без пагинации, с сортировкой по загрузке DESC. Обложка в общем списке — миниатюра **самого старого** элемента; если у него нет превью, handler не ищет следующий подходящий файл. `Create`/`Update` возвращают DTO с `CoverPath = null`, а не заново вычисленную обложку. Пользовательского выбора или порядка элементов/обложки нет. [Чтение коллекции][H-collection-get], [список][H-collection-list], [handlers][H-collections].

Удаление коллекции удаляет ее запись, но handler не меняет `CollectionId` у элементов; связь с таблицей Collections как внешний ключ не настроена. Полезная возможность — удалить организационную группу; сохранять висячие ссылки не требуется. Выбор «снять членство / удалить элементы / запретить непустую» относится к продуктовому решению. [Удаление][H-collection-delete], [DbContext][BE-db].

«Похожие» сравнивают **равенство множеств ID тегов**: число тегов равно исходному и каждый ID входит в исходный набор. Никакой оценки близости, ранжирования по пересечению, компьютерного зрения или ограничения на тот же тип/коллекцию нет. Если исходный элемент отсутствует или не имеет тегов, API возвращает `[]`. Непустой результат не ограничен числом элементов и не пагинируется. [Handler][H-similar], [тест][T-similar].

## Импорт, медиа и просмотры

Инициация импорта выдает словарь `исходное имя → presigned PUT URL` со сроком 10 часов и создает записи `WaitingForUpload` с `Unknown`. Файлы передаются напрямую в MinIO, не через тело запроса backend. Штатный запуск обработки — событие создания объекта временного bucket; явный POST является дополнительным API-путем. Ключом временного объекта служит исходное имя; индивидуального upload ID, защиты от одинаковых имен, проверки дубликатов контента или возобновления загрузки в контракте нет. [Инициация][H-upload], [watcher][P-watcher], [UI передача][UI-upload], [модель обработки][M-processing].

Фактические стадии: `WaitingForUpload → Pending → (Converting для Video) → AddedToLibrary → TemporaryFileDeleted → LibraryItemSaved → Done`; исключение в основном процессе дает `Failed`. Типы, отличные от Video, копируются в библиотеку; видео перекодируется. Внутреннее имя случайное, расширение приводится к нижнему регистру, у Video всегда `.mp4`. `UploadedOn` — UTC при создании LibraryItem после обработки, а не время выбора файла или начало передачи. Исходное имя хранится в ProcessingFile, но не возвращается в LibraryItemDto. [Модель обработки][M-processing], [сервис][P-service], [DTO][DTO-item].

| Тип | Обнаружение при штатном импорте | Результат и просмотр |
| --- | --- | --- |
| Image | MIME начинается с `image/` | Копия исходного объекта, JPEG-превью, img на detail/LightGallery. |
| Video | MIME начинается с `video/`, либо ffprobe вернул ровно `video` | MP4 H.264/AAC, длительность, JPEG-превью, video.js/LightGallery. |
| Unknown | Остальной MIME и неудача определения video | Копия объекта; специального viewer или превью не предусмотрено. |
| Text, Audio | Значения enum существуют, но автоматическая классификация в них не переводит | Это не реализованные текстовый редактор, полнотекстовый поиск или аудиоплеер. |

Текущая конверсия использует `libx264`, конфигурируемые preset/CRF, AAC 128k и MP4 faststart. Thumbnail — один JPEG шириной 300 px с сохранением пропорций; у video кадр берется на 10% длительности. Ошибка миниатюры помечает ее `Failed`, но не отменяет добавление элемента: общий processing может закончиться `Done`, а `ThumbnailPath` будет `null`. Для преобразованного видео исходник не сохраняется в библиотеке: после добавления конверсии временный объект удаляется. Для rewrite уже подтверждены готовая версия и preview без дополнительного original, сохранение исходного разрешения и автоматическое удаление временного upload-исходника после проверки результата; это [решение пользователя](06-product-questions.md), а не дополнительная функция прототипа. [Обработка][P-service].

Диалог после передачи файлов опрашивает **глобальный** список обработки каждые 2,5 секунды. API исключает и `Done`, и `Failed`; пустой список переключает диалог в «done». Поэтому «ничего не обрабатывается» не доказывает успешный импорт всех выбранных файлов, а записи ожидания неуспешно переданных файлов могут оставаться в списке. Это ограничения модели наблюдаемости, не критерии успешности rewrite. Отмена/повтор/история не представлены публичными командами. [Диалог][UI-upload], [список][P-list].

Избранное — сохраненный boolean, endpoint именно **toggle**, не присваивание значения. GET элемента сам не увеличивает просмотры. Каждый вызов increment повышает счетчик и заменяет LastView; нет дедупликации открытий, учета сессии или проверки воспроизведения видео. Detail запускает трехсекундный таймер после получения записи, отменяет его при переходе на другой ID/разрушении страницы; LightGallery в табличном режиме этот endpoint не вызывает. Поэтому счетчик отражает один конкретный путь просмотра, а не все открытия медиаконтента. [Модель][M-item], [favorite][H-favorite], [views][H-views], [detail][UI-content], [таблица][UI-list].

Удаление сначала пытается убрать сгенерированную миниатюру и объект контента, затем удаляет запись LibraryItem. Ошибки удаления объектов логируются и не останавливают удаление записи. Корзины, отката, восстановления и удаления через UI нет. Domain-метод `UpdateDescription` и поле Description существуют с лимитом 150 символов, но публичного update-description endpoint и UI редактора нет; новый импорт создает `Description = null`. [Удаление][H-delete], [модель][M-item], [controllers][BE-library].

## Карта публичного API

Все пути ниже относительно корня backend. JSON использует camelCase и строковые имена enum через `JsonStringEnumConverter`. ## Матрица трассировки и приемки

Реестр выше связывает каждую F-функцию с исходниками и минимальной приемкой. Ниже — карта существующих проверок и недостающих проверок будущего rewrite. Это план проверки сохранения поведения, а не утверждение, что эти проверки уже написаны или выполнены. Тесты текущего backend используют SQLite in-memory и handlers/repositories; они не являются end-to-end проверкой HTTP, MinIO, ffmpeg или браузера. [Основа интеграционных тестов][T-base].

## Решения и границы сохранения поведения

Вопросы о новых оригиналах, допустимых загрузках, окончательном удалении, количестве коллекций, rename тега и способе миграции/backup закрыты подтвержденными требованиями в начале документа и в [реестре решений](06-product-questions.md). Они не являются причинами останавливать проектирование или повторно запрашивать мелкие продуктовые решения.

Для остальных деталей принят текущий смысл полезных возможностей F-01…F-38:

- Имена тегов сравниваются точно, с учетом регистра (binary case-sensitive); уникальность имен не добавляется, существующие дубли сохраняются. Поддержанный язык `&&`, `||`, `!tag`, скобки сохраняется; расширение грамматики, синонимы и слияние тегов — отдельные предложения. Rename обновляет ссылки в фильтрах категорий с сохранением состава результатов.
- Коллекция остается одной nullable-принадлежностью, теги — множественной классификацией, категории — query + type. Структура плоская. Удаление коллекции снимает членство и сохраняет материалы; висячие ссылки прототипа не воспроизводятся. «Похожие» сохраняют точное равенство непустых наборов тегов; новая метрика близости не подразумевается.
- Просмотр учитывается после 3 секунд на полной странице detail, без нового условия видимости вкладки или фактического playback. Быстрый LightGallery-путь не начинает считаться просмотром автоматически. Избранное остается сохраненной отметкой; отдельная выдача — UX-предложение.
- Сохраняются семь сортировок. Для nullable duration `NULL` идет первым при ASC и последним при DESC. Random дает новый порядок при новом поиске/refresh; технический seed допустим только для согласованного обхода страниц одного контекста, без новой пользовательской настройки.
- Upload дает итог каждого файла и отделяет передачу от обработки. История, retry/cancel/resume, массовый UI, редактор описания и новые viewers не объявляются уже существующим или дополнительно одобренным scope. Их UX-предложения отделены в [аудите](05-ux-ui-audit.md).

Сохраняется полезный результат операций, а не случайные ограничения реализации: предел первых 300 записей, висячие ссылки, потеря ошибок обработки и неоднозначный результат нескольких сохранений не становятся обязательным поведением rewrite. Планируемая приемка проходит на синтетических данных; в рамках этого исследования браузер, Docker и пользовательские данные не запускались и не открывались.
